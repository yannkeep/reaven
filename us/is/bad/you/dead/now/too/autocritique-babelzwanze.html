02 / POSITIF

Ce qui marche bien

Soyons fiers de ce qu'on a accompli (sans se la raconter)

Zero dépendance lourde
VALIDÉ ▼

Tout le code est en vanilla HTML/CSS/JS. Pas de React, pas de Vue, pas de framework CSS. Juste du code pur qui tourne partout.

  • ~3500 lignes de code maintenables
  • Aucune dépendance npm
  • Poids total : ~150Ko (fonts comprises)
  • Charge même sur connexion 3G
Identité visuelle forte
VALIDÉ ▼

Le duo mint/lilas sur fond sombre crée une identité reconnaissable immédiatement. C'est pas juste "joli", c'est cohérent.

  • Palette définie en variables CSS
  • Déclinable sur tous les supports
  • Distinct des standards corporate (GAFAM)
  • Évoque le terminal/hacker sans être cliché
Transparence totale
VALIDÉ ▼

On assume tout : l'IA, les outils non testés (#àValider), les limites du projet. Pas de bullshit marketing.

  • Tag #àValider sur tous les outils non testés terrain
  • "Généré par Claude" affiché clairement
  • Ce document d'autocritique existe
  • Code source disponible
Philosophie cohérente
VALIDÉ ▼

Low-tech, libre, offline-first, imprimable, autonomisant — et on essaie vraiment de respecter ces principes.

  • Pas de trackers, pas de cookies (les digitaux)
  • Hébergeable sur n'importe quel serveur statique
  • Philosophie documentée et assumée
  • Alternative aux solutions privatrices
03 / CRITIQUE

Ce qui doit être amélioré

On se regarde en face, on note, on propose des solutions

Accessibilité insuffisante
CRITIQUE ▼

C'est le point le plus ironique : un projet d'inclusion numérique qui n'est pas fully accessible. On doit corriger ça en priorité.

  • Pas de prefers-reduced-motion pour les animations
  • Contraste insuffisant sur certains textes gris
  • Navigation clavier non testée
  • Pas de skip-to-content
  • ARIA labels manquants sur les éléments interactifs
  • Canvas non accessibles aux lecteurs d'écran
💡 SOLUTION PROPOSÉE

Audit WCAG complet + implémentation des corrections. Prévoir un mode "sobre" sans animations. Ajouter des alternatives textuelles à tous les éléments visuels.

Low-tech... vraiment ?
À VÉRIFIER ▼

On dit "low-tech" mais est-ce que ça tourne sur un PC de 2010 avec 2Go de RAM ? On n'a pas testé.

  • Canvas multiples = potentiellement gourmand
  • Animations complexes sans fallback
  • Fonts Google = dépendance externe
  • Pas de version "lite" sans effets
💡 SOLUTION PROPOSÉE

Tester sur vieux matos. Créer une version "lite". Embarquer les fonts en local. Ajouter détection de performance pour désactiver les effets lourds.

Outils non validés terrain
EN ATTENTE ▼

Le catalogue liste 16 outils mais aucun n'a été testé en situation réelle avec le public cible (EPN, formateurs, apprenants).

  • Fiches rédigées par l'IA, pas par des formateurs
  • Pas de retours utilisateurs
  • Contexte belge pas vérifié (itsme, Tax-on-web...)
  • Durées et difficultés = estimations
💡 SOLUTION PROPOSÉE

Partenariat avec des EPN pour tests terrain. Chaque outil validé perd son tag #àValider. Feedback loop avec les formateurs.

Structure monolithique
TECHNIQUE ▼

Tout dans un seul fichier HTML c'est pratique pour la démo mais pas maintenable à long terme.

  • 3500+ lignes dans un fichier = difficilement éditable
  • Pas de versioning granulaire
  • CSS et JS mélangés
  • Pas de build process
💡 SOLUTION PROPOSÉE

Séparer en composants modulaires. Utiliser un build simple (juste concat, pas de bundler lourd). Permettre l'édition par non-devs via fichiers séparés.

Pas de version imprimable
EN COURS ▼

On dit "imprimable" dans les principes mais il n'y a pas de PDF téléchargeable ni de styles d'impression optimisés.

  • Fiches outils pas disponibles en PDF
  • Styles @media print minimaux
  • Pas de version "livret" pour impression
💡 SOLUTION PROPOSÉE

Générer des PDF pour chaque fiche outil. Créer un livret complet imprimable. Optimiser les styles print.

Public cible flou
RÉFLEXION ▼

Est-ce que le niveau de "wow effect" est adapté ? Un formateur EPN veut-il vraiment des particules et du néon ?

  • Démo impressionnante vs outil pratique
  • Esthétique "hacker" peut intimider
  • Pas d'étude des besoins réels
💡 SOLUTION PROPOSÉE

Sondage auprès du public cible. Proposer plusieurs "skins" (sobre, fun, accessible). Adapter selon les retours.

05 / QUESTIONS

Questions ouvertes

On n'a pas toutes les réponses. Et c'est OK.

IA : atout ou problème ?
DÉBAT ▼

Ce projet est largement généré par IA. Est-ce cohérent avec une philosophie de réappropriation technologique ? Ou est-ce justement un exemple de comment utiliser l'IA de manière éthique et transparente ?

On assume le choix : l'IA est un outil, pas un remplacement. L'humain garde le contrôle éditorial et stratégique. Mais la question mérite d'être posée.

Gouvernance future ?
OUVERT ▼

Qui décide de quoi à long terme ? Une personne ? Un collectif ? Comment on évite que le projet soit abandonné si l'IB n'est plus disponible ?

Pistes : documentation exhaustive, formation de relais, structure associative, modèle wiki ouvert...

Modèle économique ?
FLOU ▼

Tout est gratuit et libre. Super. Mais qui paie l'hébergement ? Qui a le temps de maintenir ? Comment ça tient dans la durée sans financement ?

Pistes : bénévolat pur, subsides associatifs, dons, modèle "pay what you want"...
